## S13 实际业务资料

每类提供一张代表性拓扑的脱敏文本即可，已有 v3 JSON 也可直接作为输入：

| 场景 | 需要确认的关系与运行数据 | 当前来源 |
| --- | --- | --- |
| 地面站 | 天线、收发基带、功放、LNB、网络/服务器；射频/中频/控制/网络连接；至少一个正常、告警、离线实例 | 只有内置演示图，真实资料待提供 |
| 机房 | 核心网络、交换机、业务/存储服务器及管理网；并行连接和主备规则；参数、真实状态及断流行为 | 同上 |
| 卫星逻辑 | 子系统、模块、服务和控制/业务/状态逻辑关系；需要的层级/子拓扑；参数和状态语义 | 同上 |

资料内容：

1. 图名、用途、预期节点/链路规模，哪些位置与走线必须保留。
2. 各节点名称、模板类型、脱敏业务 ID；显示哪些参数、单位和小数位数，是否含零参数节点。
3. 每条连接的两端、类型、标签、方向、正常/断开/空闲语义。视觉连接口可以汇聚，不要求每条逻辑线对应一个物理端口。
4. 一条实际宿主数据消息及其字段含义，业务状态如何映射 normal/warning/offline、链路 up/down/unknown；采集周期和可接受超时时间。只有脱敏样例时明确标注，暂不要求提供采集服务凭据。
5. 是否关联子拓扑、发布展示应使用哪版，以及一个预期的故障/断流/恢复过程。

缺少部分数据时先记录具体缺项，能制作的图仍可制作；没有业务来源与确认人的图只能记为流程预演。

## 每张实际图的验收步骤

1. **制作**：新建/导入、命名、配置模板/参数/状态映射，手工排列节点和拐点；补区域、注释、图例、子图引用。对照原始清单确认节点与连接数、标签和方向，记录任何表达困难。
2. **编辑**：多选、复制、对齐/分布和锁定各做一次；一步撤销恢复原布局及手工拐点，确认汇聚连接口可用。无参数、长名称与复杂交汇处单独观察。
3. **保存恢复**：修改后等自动草稿完成，刷新/切图后恢复；手动保存与草稿区别清楚，导出 JSON 并重新导入对照配置，不把运行值或接收时间带进配置。
4. **发布**：首次发布并打开跟随页，制作端再改草稿确认展示不变；第二次发布确认切版；查看固定历史并回滚，确认版本追溯且草稿不被覆盖。
5. **宿主展示**：按真实业务 ID/绑定输入正常、告警、离线和局部更新；检查节点文字/参数、链路状态/动效以及等待、超时、断开、重连后需新数据的行为。搜索、小地图、关联聚焦与父子图返回不改原布局。
6. **导出**：PNG 实际打开，SVG 在独立窗口打开，HTML 下载后断网打开；逐一确认参数/状态快照和人工位置，HTML 再使用宿主 API 更新。静态图只保留静态外观，HTML 的首次实时更新切入时效判断。
7. **业务结论**：记录耗时、最易误操作的步骤、需要补充的设备/连线表达、问题复现及处理结论。由实际使用者确认可用或列出必须修复项；未确认的项保留待验收。

每图证据建议包含：原始业务清单、最终 JSON、发布 ID/rN、PNG/SVG/HTML、宿主脱敏消息、至少一张故障状态图、恢复过程及问题记录。资料可以保存于团队指定位置，仓库内只记录脱敏内容和证据位置。
