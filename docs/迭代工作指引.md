## 工作规则

1. 按步骤推进，优先修复阻碍当前步骤的问题。保留人工布局和手工走线，自动整理提供可撤销的操作。
2. 每项工作明确范围、验收标准、测试结果和遗留项。状态使用“待开始、进行中、待验收、已完成”。
3. “已完成”表示实现和该步骤必需验证均通过。代码已实现而浏览器验收受限时记录“待验收”，不将用例列举或构建成功视为浏览器通过。
4. 因环境限制无法完成的检查须保留准确报错、复现命令及重新验收方法。其他独立工作可继续，相关发布验收保持待办。
5. 新增依赖统一使用 `bun install`。修改文件格式时同步维护 Schema、迁移逻辑、导出及独立展示组件。
6. 每步完成实现后运行相关测试和构建；有新失败或实质变更时再追加检查。涉及交互时运行对应浏览器用例。
7. 更新 README 和接入说明中受到影响的行为；维护本文件中的状态、检查清单及迭代记录。
8. 完成一个可预览的批次后执行 `bun run deploy`。区分构建成功、上传成功和页面验收，不将预览部署等同于正式发布。
9. 版本提交和推送按用户指令执行，不自动提交未审核的改动。

## S02 自动保存、草稿恢复和本地历史版本

### 本批次范围

- 编辑停止约 1.25 秒后保存草稿；刷新和切图自动恢复有效草稿。手动保存单独更新已保存版本。
- 工具栏增加“草稿与历史”，支持查看时间、手动重试、恢复历史及保留恢复前内容。
- 每张图最多 10 个历史版本，全库最多 40 个历史版本且历史快照总量控制在约 1.5 MB；不删除当前草稿来腾出历史空间。
- 自动草稿保留较早检查点，至少间隔 60 秒；手动保存和恢复前建立版本。恢复先保留当前内容，再替换为可撤销的草稿。
- 草稿和历史作为拓扑库的附加编辑元数据保存，与库在同一次本地存储写入中更新；通用文件格式及独立展示组件不变。
- 检测其他标签页写入时暂停保存，提供导出当前图和重新读取入口。本地存储的检测不提供服务端事务级的多人并发保证。

### 实施约束

- 保留现有通用文档和拓扑库兼容性。草稿按文档 ID 隔离，恢复过程先校验后替换。
- 自动保存需延迟合并频繁编辑；单次保存失败不丢失当前画布，也不把失败状态显示为已保存。
- 草稿、手动保存和后续发布版本使用明确名称，避免自动保存直接影响正式展示。
- 本地历史使用有限数量和容量；恢复版本本身也可撤销或回退。删除文档时清理所属草稿，避免孤立恢复。
- 验证刷新、切图、导入、删除、恢复、损坏存储、配额不足和多标签页冲突。
